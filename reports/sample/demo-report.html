1. Apache 2.4.49 is vulnerable to CVE-2021-41773 (path traversal / RCE)

CVSS ~9.8 · CWE-22 · A06:2021 Vulnerable and Outdated Components · confidence: certain

What we found

This exact Apache version is affected by CVE-2021-41773 / CVE-2021-42013: a path traversal flaw in mod_proxy that allows reading files outside the document root and, with mod_cgi enabled, remote code execution.

Business impact

Unauthenticated remote code execution on the web server.

Evidence

  • Server: Apache/2.4.49

How to fix it

Upgrade to Apache 2.4.51 or later immediately. As an interim mitigation, disable mod_cgi and require 'Require all denied' on the default filesystem path.
Category: Outdated Software Effort: Quick fix (under 1 hour) Location: http://127.0.0.1:8099
critical

2. CORS reflects any origin with credentials enabled

CVSS ~9.3 · CWE-942 · A01:2021 Broken Access Control · confidence: certain

What we found

http://127.0.0.1:8099/ returned Access-Control-Allow-Origin: https://vulnscope-canary.example together with Access-Control-Allow-Credentials: true. Any website on the internet can therefore make authenticated cross-origin requests and read the responses as the logged-in victim.

Business impact

Complete account takeover from a single malicious link: the attacker reads profile data, API tokens and personal information, and can perform actions on the victim's behalf.

Evidence

  • GET http://127.0.0.1:8099/
  • Origin: https://vulnscope-canary.example
  • Access-Control-Allow-Origin: https://vulnscope-canary.example
  • Access-Control-Allow-Credentials: true

How to fix it

Never reflect the Origin header blindly. Use a strict allow-list:
if origin in TRUSTED_ORIGINS: set ACAO=origin, ACAC=true
else: do not send CORS headers at all.
Also reject the 'null' origin.
Category: Misconfiguration Effort: Quick fix (under 1 hour) Location: http://127.0.0.1:8099/

4. Environment file with secrets exposed

CVSS ~9.8 · CWE-538 · A02:2021 Cryptographic Failures · confidence: certain

What we found

The .env file is downloadable. It normally contains database credentials, the application encryption key, mail passwords and third-party API keys.

Business impact

Direct database access, ability to forge session cookies with the app key, and full compromise of every integrated service.

Evidence

  • GET http://127.0.0.1:8099/.env -> HTTP 200 (68 bytes)
  • First lines: APP_NAME=TestShop | APP_KEY=base64:abcd1234SECRET

How to fix it

Deny access to dotfiles at the server, move the file above the web root, and rotate every credential it contains:
location ~ /\.(?!well-known) { deny all; }
Category: Sensitive File Exposure Effort: Quick fix (under 1 hour) Location: http://127.0.0.1:8099/.env

5. Exposed Git repository configuration

CVSS ~9.8 · CWE-538 · A05:2021 Security Misconfiguration · confidence: certain

What we found

The .git directory is publicly readable. An attacker can download the entire source history - including secrets that were committed and later 'removed' - and then reconstruct the full application source.

Business impact

Complete source code disclosure, plus every credential, API key and database password that ever appeared in a commit. This typically leads to full server compromise.

Evidence

  • GET http://127.0.0.1:8099/.git/config -> HTTP 200 (50 bytes)

How to fix it

Block access at the web server and rotate any secret that was ever committed:
location ~ /\.git { deny all; return 404; }
Then rebuild the repository without the leaked secrets and force-push.
Category: Sensitive File Exposure Effort: Quick fix (under 1 hour) Location: http://127.0.0.1:8099/.git/config

6. Path traversal / local file inclusion in 'file'

CVSS ~9.1 · CWE-22 · A01:2021 Broken Access Control · confidence: certain

What we found

A relative path payload caused the server to return the contents of /etc/passwd. The parameter is used to build a filesystem path without validation or confinement to a base directory.

Business impact

Read of arbitrary server files - configuration, private keys, database credentials - and often escalation to remote code execution by including a file the attacker can upload.

Evidence

  • GET http://127.0.0.1:8099/download?file=..%2F..%2F..%2F..%2F..%2F..%2Fetc%2Fpasswd
  • Response contained 'root:x:0:0:'

How to fix it

Never pass user input to file APIs. Resolve the path and verify it stays inside the allowed directory:
real = os.path.realpath(os.path.join(BASE, name))
if not real.startswith(BASE + os.sep): abort(400)
Better: map an opaque ID to a stored path instead of accepting names.
Category: Injection Effort: Involved (1-3 days) Location: http://127.0.0.1:8099/download?file=report.txt
critical

7. SQL injection in parameter 'q' (MySQL)

CVSS ~9.8 · CWE-89 · A03:2021 Injection · confidence: certain

What we found

Appending a single quote to 'q' produced a raw MySQL database error that does not appear on the normal page. The value is being concatenated directly into a SQL statement instead of being sent as a bound parameter.

Business impact

Full database read and write: customer records, password hashes, payment data and admin credentials. Depending on database privileges this often escalates to remote code execution on the server. This is a reportable data-breach risk.

Evidence

  • GET http://127.0.0.1:8099/search?q=1%27
  • Database error signature: you have an error in your sql syntax

How to fix it

Use parameterised queries / prepared statements everywhere. Never build SQL by string concatenation.
PHP: $stmt = $pdo->prepare('SELECT * FROM t WHERE id = ?');
Java: PreparedStatement with setInt/setString
Also apply least-privilege DB accounts and disable detailed DB errors in production.
Category: Injection Effort: Involved (1-3 days) Location: http://127.0.0.1:8099/search
critical

9. Content-Security-Policy header is missing

CVSS ~6.1 · CWE-693 · A05:2021 Security Misconfiguration · confidence: certain

What we found

Without a CSP the browser will execute any script that reaches the page. This is the single most effective defence-in-depth control against cross-site scripting (XSS), malicious third-party scripts and data injection.

Business impact

Raises the likelihood and blast radius of any injection flaw on the site; an attacker who lands one script gets a durable foothold in users' browsers.

Evidence

  • GET http://127.0.0.1:8099/
  • Response headers did not include: content-security-policy

How to fix it

Publish a restrictive CSP, starting in report-only mode:
Content-Security-Policy: default-src 'self'; script-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'self'
Category: Security Headers Effort: Quick fix (under 1 hour) Location: http://127.0.0.1:8099/

13. Reflected XSS in parameter 'name'

CVSS ~6.1 · CWE-79 · A03:2021 Injection · confidence: firm

What we found

User input supplied in 'name' is written back into the HTML page without encoding. The probe string was returned with its angle brackets intact, which means an attacker can inject any HTML tag - including <script> - and it will execute in the victim's browser.

Business impact

Session theft, credential phishing rendered inside your own page, silent actions on behalf of the user, and malware delivery. Chained with a missing HttpOnly flag this is immediate account takeover.

Evidence

  • GET http://127.0.0.1:8099/render?name=vswfr6d8f0%3Cvswfr6d8f0%3E
  • Payload fragment reflected verbatim: <vswfr6d8f0>
  • Response length: 54 bytes

How to fix it

Context-aware output encoding on every sink:
- HTML body: encode & < > " '
- attributes: quote and encode
- JavaScript/URL contexts: use the framework's escaper
Also validate input against an allow-list and add a strict CSP as defence in depth.
Category: Injection Effort: Moderate (half a day) Location: http://127.0.0.1:8099/render?name=guest

17. HTTP TRACE method is enabled

CVSS ~5.3 · CWE-749 · A05:2021 Security Misconfiguration · confidence: certain

What we found

The server answers TRACE by echoing the full request back, including headers. Combined with a scripting flaw this enables Cross-Site Tracing (XST), which can read HttpOnly cookies.

Business impact

Bypasses the HttpOnly protection on session cookies in some browsers.

Evidence

  • TRACE http://127.0.0.1:8099 -> HTTP 200

How to fix it

Disable TRACE at the web server:
Apache: TraceEnable Off
nginx: if ($request_method = TRACE) { return 405; }
Category: Misconfiguration Effort: Quick fix (under 1 hour) Location: http://127.0.0.1:8099

CVSS ~6.1 · CWE-601 · A01:2021 Broken Access Control · confidence: certain

The 'url' parameter controls where the user is sent, and it accepts any external host. The application will happily redirect visitors to an attacker-controlled site while the link still starts with your domain.

CVSS ~3.1 · CWE-693 · A05:2021 Security Misconfiguration · confidence: certain

What we found

COOP isolates your browsing context from cross-origin windows, closing cross-window attacks such as Spectre-style leaks and tabnabbing chains.

Business impact

Raises the likelihood and blast radius of any injection flaw on the site; an attacker who lands one script gets a durable foothold in users' browsers.

Evidence

  • GET http://127.0.0.1:8099/
  • Response headers did not include: cross-origin-opener-policy

How to fix it

Add:
Cross-Origin-Opener-Policy: same-origin
Category: Security Headers Effort: Quick fix (under 1 hour) Location: http://127.0.0.1:8099/

33. robots.txt points at sensitive paths

CWE-200 · A05:2021 Security Misconfiguration · confidence: certain

What we found

robots.txt lists directories that look sensitive. Bots ignore this file, and it is often the first thing an attacker reads - it works as a signpost rather than a control.

Business impact

Guides attackers to admin, backup or internal paths.

Evidence

How to fix it

Do not rely on robots.txt for access control. Protect these paths with real authentication and remove the hints.

Methodology, scope & limitations

What was tested

  • Transport encryption, certificate validity and protocol support
  • HTTP security headers, cookie attributes and browser hardening
  • Server configuration: HTTP methods, CORS policy, error handling, host header trust
  • Exposure of backups, configuration files, repositories and admin panels
  • Technology fingerprinting and outdated component detection
  • Client-side content: mixed content, leaked secrets, third-party script integrity
  • DNS and email authentication: SPF, DMARC, DKIM, CAA, DNSSEC
  • Non-destructive injection probes on discovered parameters (reflected XSS, SQL error signatures, open redirect, path traversal, template injection, CRLF)

What this scan does not replace

  • Authenticated testing of logged-in roles and privilege boundaries
  • Business-logic abuse (price manipulation, workflow bypass, race conditions)
  • Mobile application and API client testing
  • Source-code review and infrastructure / network penetration testing
  • Social engineering and physical access

Findings are based on external observation only. Absence of a finding does not prove absence of a vulnerability.

How severity is assigned

critical Direct path to full compromise or mass data disclosure. Exploitable by an unskilled attacker, often without authentication. Fix immediately.
high Serious weakness that leads to account or data compromise, or a clear compliance failure. Fix within days.
medium Weakens defences or requires chaining with another flaw. Fix within weeks.
low Hardening gap with limited direct impact. Fix on a normal maintenance cycle.
info Observation, best-practice note, or context for the other findings.
